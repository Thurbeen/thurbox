init, up and apply

Three commands take Fleet from nothing to a running agent session.

fleet init # 

fleet init

Writes Fleet's config, ~/.config/fleet/config.toml, with one runtime, runtime-mux, and one place, local: this machine. It prints the config path, the places, the coding agents it found on PATH, and what to run next. It works offline. The config is yours once written: a second fleet init checks it and keeps it.

fleet up # 

fleet up

The manager. It runs in the foreground and keeps every Task moving: it starts sessions, sends briefs, delivers messages and records results. It creates no Task of its own. Ctrl+C stops it and leaves the sessions running; the next fleet up picks them up again. Only one manager runs per Fleet. fleet version --json says whether one runs. To keep it running without a terminal, see Keep fleet up running.

fleet apply #

A Task is a JSON file. This one runs Claude Code in a worktree of a local repository:

{
  "apiVersion": "fleet/v1alpha1",
  "kind": "Task",
  "metadata": {"name": "fix-login"},
  "spec": {
    "harness": "claude",
    "host": "local",
    "brief": "Fix the login redirect and run the tests.",
    "workspace": ["git+file:///home/me/app"],
    "dispatch": true
  }
}
fleet apply -f fix-login.json
fleet list task
fleet status task fix-login --json
  • harness is the agent (Agents), and host the place.
  • workspace lists URLs. With git+file://, the runtime makes a git worktree on a new branch; file:// uses the directory as it is; [] starts the agent in the runtime's default directory.
  • Nothing starts while dispatch is false, the default.
  • Leave brief out and the session waits for you to type.

fleet apply creates or updates; --create-only refuses a name that is taken. -f - reads the JSON from stdin. Every field is in the Task resource.
