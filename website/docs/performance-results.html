Times are milliseconds, memory is MiB, CPU is percent of one core and wakeups are received scheduler events per second unless the row states a count. Absolute deltas are wrapped minus raw; percentage deltas divide by the unrounded raw value. Display rounding can hide small nonzero baselines. A negative growth value is measured memory contraction; dividing a delta by negative raw growth gives an arithmetic percentage, not a positive growth-rate interpretation.

Download the per-run metric observations and source/tool metadata. These numeric records exclude process arguments, local paths and private logs. The legacy five-second resource rows omit reaped helper CPU; the sixty-five-second family rows are authoritative for default idle cost. Codex whole-stack memory includes its agent, while synthetic-agent host measurements exclude agents.

Ranked remaining gaps

These are diagnoses of the measured source, with proposed fixes. No product patch or projected speedup is represented as a completed optimization.

  1. RMUX hidden-output input loss. The correctly focused release fixture delivered ten inputs through raw RMUX and none through the wrapper. Control-reader EOF closes pane senders; existing writers retain the old connection's stdin. Rebind both directions during recovery and verify input delivery under hidden output. The measured opportunity is recovery of the missing inputs and removal of observed reconnect stalls. A separate wire trace receives nine %exit too far behind messages from RMUX before repeated BrokenPipe/reconnect cycles, confirming lagged subscriptions in that diagnostic. RMUX output-cursor lag handling emits that exit. Tracing changes the producer/drain race; this is trigger evidence, rather than a release timing. Reader teardown; writer connection ownership.
  2. Default idle process probes. Twenty attached sessions consume 20.89% and 25.63% of one core. Hook-covered controls reduce the wrapped medians to 2.80% and 4.28%; steady user-cycle profiles attribute 66.16% and 59.10% to ps. Missing hook state causes per-pane foreground discovery. Batch process discovery and cache identities while preserving unhooked-agent support. The observed conditional reductions are about 18.1 and 21.4 percentage points, with a remaining residual above raw. Probe fallback; per-TTY process query.
  3. RMUX nested reply accounting. Conditional resize emits several empty replies while the adapter expects one; those replies consume snapshot waiters. Valid first snapshots are ignored, followed by retries 2.24 seconds later on attach and 2.014 seconds later on switch in the diagnostic trace. Use operation-specific reply accounting or explicit command ownership. Those retry intervals are measured components, not a promised final attach time. Single-reply override; two-second retry.
  4. Renderer and keeper memory. The release renderer contributes about 20 MiB PSS in either adapter: 10.594 MiB of mapped executable pages and roughly 8.5 MiB anonymous/heap memory. RMUX also starts a tmux heartbeat service because heartbeat uses the platform-default registry backend. Keeper on/off controls measure 2.573/7.232 MiB extra PSS at twenty sessions. Reuse the selected backend where appropriate and create keeper infrastructure lazily; the renderer has a separate footprint. Disabling a feature is a conditional control, not default parity. In the final cohort, persistent renderer anonymous/heap PSS grows by 3.695/3.387 MiB between 900 and 6300 seconds. Raw RMUX’s executable PSS contracts while its executable RSS is unchanged: page sharing changes, rather than anonymous memory being freed. Those diagnostic endpoints are separate from the repeated median growth statistic. A three-pair four-arena control reduces median aligned anonymous mappings from 31 to 3 and renderer anonymous/heap PSS by about 1.24/1.13 MiB, beyond the observed condition ranges. This supports allocator-retained memory as part of the footprint; it does not identify an allocating callsite, establish a leak or measure tuned long-soak growth. Registry default; heartbeat backend.
  5. Output parsing, paint scheduling and whole-grid work. The output floor is 33 ms and input floor 16 ms. Repaint user-cycle profiles attribute about 15% to PseudoTerminal rendering, 5–7% to cell cloning, plus styles, equality and buffer application. Two of five traced tmux Codex echoes wait another 27–30 ms after control output arrives. Other traced echoes do not reproduce that delay, and tracing changes the race, so this does not explain the entire 43–46 ms release median excess. Preserve immediate arrived-echo painting, reduce whole-grid work and schedule paint deadlines independently of coarse polling. Per-key sequence reservation versus coalesced output remains a candidate requiring confirmation. Direct release counters record 26.6 paints/s for tmux at both producer rates and RMUX at 60 Hz. Two quiet RMUX 30 Hz cohorts slow to 6.6–7.8 paints/s in late windows, with stopped echo progress. A retained log shows the writer exiting while producer frames continue; the exact initiating lifetime/liveness path is unconfirmed. Three separately wire-traced runs do not reproduce that exit, so they do not clear the quiet-run failure. These are all paints, rather than distinct producer frames. A separate twelve-burst plain-output profile attributes 16.41%/11.75% of wrapped user cycles to vt100 character insertion and 9.45% of wrapped RMUX cycles to octal decoding. Reuse decode buffers and evaluate a UTF-8/control-correct parsing fast path. These samples combine production and delivery; they cannot predict how much of the release producer excess a parser patch removes. Paint scheduling; echo sequencing; terminal widget; octal decoding.
  6. Large-history search. At twenty 10,000-line histories, warm queries take about 77.5/109.7 ms and typing 75.1 ms against a 50 ms budget. Lock time is about 1.05 ms against 1 ms; 33.1 ms rescan passes. The 1,000-line fixture passes. Mixed cold/warm search samples attribute 21.53% to row text extraction, 14.90% to string search, 7.81% to character search and 7.45% to folded matching.
