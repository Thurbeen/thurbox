Removing Thurbox's old hook entries

Thurbox v3 installs nothing into a coding agent's configuration. Session status comes from Fleet : each Fleet harness profile passes the agent its hooks when Fleet launches it, so no agent's own config file is changed.

Thurbox v2 worked differently. Its built-in hooks extension wrote status hooks into each agent's config, and its ui-skill and sessions-skill extensions copied two skills into each agent's skill directory. Thurbox v3 does not remove them. The hooks call thurbox-cli session signal , a command that no longer exists. Each one ends in || true (or || exit 0 ), so it fails without harm, but it still runs on every agent event. Delete them by hand with the steps below. Skip any agent you never used: v2 wrote a file only when that agent's directory already existed.

How to recognise Thurbox's entries #

  • A hook command that runs thurbox-cli session signal (codex's also runs thurbox-cli session bind-codex ).
  • The text managed by thurbox `extension install` (any capitalisation), at the end of a hook command, in a comment above a merged entry, or in the comment at the top of a script or TOML file Thurbox wrote.
  • On an SSH or WSL host, the same entries call tmux set-option -p @thurbox_state (or psmux … set-option -p @thurbox_state ) in place of thurbox-cli session signal .

A hook that you wrote yourself has none of these. Leave it.

Entries merged into a file you own #

In these files, delete only Thurbox's entries and keep the rest of the file.

Agent File What to delete
claude ~/.config/thurbox/agents.toml The two arguments "--settings" and the path ending in thurbox/hooks/claude.json from the args of the claude agent. Also check every custom agent with hook_schema = "claude" and every agent that extends one of them.
aider ~/.config/thurbox/agents.toml The three arguments "--notifications" , "--notifications-command" and "thurbox-cli session signal --state blocked" from the args of the aider agent, and of each agent with hook_schema = "aider" .
codex ~/.codex/hooks.json , and hooks.json in every other CODEX_HOME you used Each hook whose command calls thurbox-cli , and the SessionStart hook that echo s an instruction starting with thurbox: . Delete an event's list when it becomes empty.
antigravity ~/.gemini/settings.json Each hook under hooks whose command calls thurbox-cli session signal (events SessionStart , PreToolUse , PostToolUse , Notification , Stop ).
kimi ~/.kimi-code/config.toml Each [[hooks]] table under the comment # managed by thurbox `extension install` — do not edit , and that comment.

Your agents' list lives in ~/.config/thurbox-dev/agents.toml for a development build, and in %APPDATA%\thurbox\agents.toml on Windows.

Files Thurbox wrote #

Delete each of these files. Open it first and do the check in the last column: if the marker is not there, it is your own file, so keep it.

Agent File Thurbox's file if
opencode ~/.config/opencode/plugin/thurbox-status.js The first line is // Managed by thurbox `extension install` .
vibe ~/.vibe/hooks.toml The first line is # Managed by thurbox `extension install` .
pi ~/.pi/agent/extensions/thurbox-status.ts The first line is // Managed by thurbox `extension install` .
omp ~/.omp/agent/extensions/thurbox-status.ts The first line is // Managed by thurbox `extension install` .
copilot ~/.copilot/hooks/thurbox-status.json The file is JSON and starts with { . Search the whole file for managed by thurbox : it is at the end of the first hook's bash and powershell commands.
grok ~/.grok/hooks/thurbox-status.json The file is JSON and starts with { . Search the whole file for managed by thurbox : it is at the end of the SessionStart hook's command .

Skills #

ui-skill copied a thurbox-ui skill and sessions-skill copied a thurbox-sessions skill into these directories. Each SKILL.md carries the managed by thurbox marker. Delete the thurbox-ui and thurbox-sessions directories in each one:

  • ~/.claude/skills/
  • ~/.codex/skills/
  • ~/.config/opencode/skills/
  • ~/.copilot/skills/
  • ~/.agents/skills/

Thurbox's own leftovers #

Thurbox v3 reads none of these. Delete them:

  • ~/.config/thurbox/hooks/ — it held claude.json , the file the --settings argument above pointed at.
  • In ~/.config/thurbox/extensions/ , only the three built-in extensions' entries: the manifests hooks.toml , ui-skill.toml and sessions-skill.toml , and the ui-skill/ and sessions-skill/ directories if they are there.
  • ~/.config/thurbox/hooks.toml — nothing runs session lifecycle hooks.

Do not delete the whole ~/.config/thurbox/extensions/ directory. Any other manifest or directory in it belongs to an extension you installed yourself, and can hold your own files or data. Look at it, and back it up, before you delete it.

A development build uses ~/.config/thurbox-dev/ in place of ~/.config/thurbox/ .

Windows and remote hosts #

On Windows, each ~ path above is under %USERPROFILE% , and Thurbox's own directories are under %APPDATA%\thurbox .

On an SSH or WSL host where Thurbox v2 ran agents, it wrote the same hook entries and status files into that host's agent directories. Log in to each host with ssh <host> or wsl -d <distro> and do the same steps there. On a host, the hook commands set the @thurbox_state pane option in place of calling thurbox-cli .
