thurbox TUI — UI/UX Review

thurbox 0.0.0-dev theme: Doom generated 2026-06-14 08:44 UTC

This page is generated by the ui-review skill: it drives the real TUI in an isolated sandbox, screenshots every screen, and critiques each through four lenses — visual design, usability, consistency, and accessibility. Re-run the skill to refresh it.

Summary — 23 findings across 10 screens

9 warnings 14 nits 9 visual 7 usability 5 consistency 2 accessibility

Top recommendations

  1. Add a non-color cue (glyph or letter) to session status dots so Waiting / Running / Attention is readable without relying on the red/green hue alone.
  2. Humanize the cron expression in the automations pane and the session-list automation summary line (e.g. "daily 09:00" instead of "0 9 * * *"), and brighten that dim summary row so it is legible.
  3. Tighten the empty-state copy across the file viewer and repo picker — give the empty repo tree and the "No bookmarks" picker an actionable one-liner pointing at the key that adds content.
  4. Raise the contrast of the selected-session highlight in the Doom theme: red text on a maroon selection band is hard to read; use a brighter foreground or a clearly distinct selection background.
  5. Make the info-panel meter rows self-labeling (units + thresholds) so Memory / CPU / disk bars communicate at a glance instead of needing the user to decode tiny bars.

Session list + terminal (default view) launch

warning
Session status conveyed by color alone accessibility
Each session row is prefixed by a small red or green dot to signal status, with no text or shape backup. Red/green is the single most common color-vision deficiency pairing, so the state is invisible to a meaningful share of users.
Fix: Pair the dot with a one-glyph status marker (e.g. ● running, ○ waiting, ⚠ attention) or a short status letter so the state survives in grayscale.
warning
Automation summary row is cryptic and dim visual
The row at the foot of the session list ("·L· — 0 9 * * * · spawn · in 22h 15m") packs a raw cron expression, an action verb and a countdown into one heavily dimmed line. It is the least legible element on screen and its leading "·L·" token reads as noise.
Fix: Drop the cryptic prefix, render the schedule in human terms ("daily 09:00"), and lift the foreground a notch so the row is readable without being mistaken for a separator.
nit
Header agent label vs. selected session can drift consistency
The top-right shows the active agent name ("gemini") and theme ("Doom"); this is a nice anchor, but it duplicates information already implied by the highlighted session and adds a second place to keep in sync.
Fix: Keep it, but ensure the header agent label always tracks the focused session so the two never disagree during navigation.

A different session selected Ctrl+J

warning
Low-contrast selected-session highlight visual
The focused session ("claude") is marked with a maroon selection band, but the row text stays in the same red family, so foreground and background are close in hue and luminance — the selected row does not pop the way a primary selection should.
Fix: Use a brighter or near-white foreground for the selected row, or a selection background with clearly higher luminance contrast against the red text (target ≥ 4.5:1).
nit
Selection styling differs between list and terminal diff consistency
The session-list selection is a flat maroon band while the terminal's code diff uses saturated green/red full-width bars. Two different "highlighted line" idioms sit a few columns apart, which slightly muddies what "selected" means.
Fix: This is mostly the agent's own output, but consider a distinct selection treatment (e.g. an accent left-border) for the session list so it never reads as a diff line.

Session info panel Ctrl+B

warning
Meter rows are hard to decode at panel width visual
Memory (191.1 MB), a CPU bar at 20% and a disk bar (12.3/31.3 GB) render as very short progress bars in a narrow column; the bars carry little information and the percentages/units sit apart from them.
Fix: Right-align the numeric value next to each bar and add a unit/threshold so the row is self-describing; consider color-coding only as a secondary cue past a threshold.
nit
"not logged in (no subscription token)" reads as an error usability
The Usage section shows "not logged in (no subscription token)" in the same weight as data rows, which can alarm a user who is in fact authenticated via the system keyring.
Fix: Soften the copy ("usage unavailable — no token") and visually demote it so it reads as 'no data' rather than a failure.
nit
Automation countdown duplicated verbatim consistency
The info panel repeats the same "in 22h 15m / nightly-triage" string that already appears in the session-list summary row, in a different layout.
Fix: Share one formatter for relative automation times so the two surfaces stay byte-identical and consistent.

File viewer (repo tree) Ctrl+E

warning
File viewer opens to a near-empty tree usability
The viewer shows only the "sample-project" root with little visible structure, and there is no hint that the tree is collapsed vs. genuinely empty. A first-time user can't tell whether to expand, refresh, or that the repo simply has no tracked files.
Fix: Auto-expand the first level (or the active file's path) on open, and show an explicit empty/collapsed-state line when the tree has nothing to show.
nit
File-viewer footer hints are densely packed visual
The viewer footer crams j/k move, n/N, collapse/expand, open, search and next/prev into one line of small dim text, which is hard to parse mid-task.
Fix: Group the hints by purpose (navigate | open | search) with subtle separators, or show only the most relevant subset for the current focus.

Tasks panel (todo list) Ctrl+W

warning
Task status relies on checkbox glyph + color only accessibility
Tasks use ☐/◐/☑ glyphs which is good, but the panel and the central detail lean on red foreground for everything, so Todo vs InProgress vs Done is carried mainly by the glyph; at small sizes the half-filled ◐ (InProgress) is easy to misread as Done.
Fix: Add a short status word in the detail header and consider distinct hues for the three glyphs so the in-progress state is unmistakable.
nit
Good empty-description affordance — extend the pattern usability
The detail pane's "No description — press e to add notes." is an exemplary empty state: it names the key and the outcome. This pattern is missing from the file viewer and repo picker.
Fix: Reuse this "<empty state> — press <key> to <action>" template across all empty panels for consistency.
nit
Task detail labels are well-aligned consistency
The agent/session/status/source/created/updated rows are cleanly key-aligned and readable — a model the info panel's meter rows could follow.
Fix: Adopt this same left-label / value-column alignment in the Ctrl+B info panel.

Automations pane Ctrl+P

warning
Raw cron expression in the automations list usability
The automation renders its schedule as "0 9 * * *", which most users cannot read at a glance and which obscures the actual fire time. The adjacent "· spawn · in 22h 15m" helps but the cron string is still the primary label.
Fix: Show a humanized schedule as the primary text ("Daily at 09:00") and keep the cron expression as secondary/edit-time detail.
nit
Pane overlay sits close to terminal banner visual
The automations overlay pops near the top-left and overlaps the agent banner area, so its border briefly competes with the terminal art behind it.
Fix: Give the overlay a solid (non-transparent) background fill behind its border so it reads as clearly layered above the terminal.

Global search strip Ctrl+A + query

nit
Clear, well-structured search strip visual
The strip shows the query, a per-scope count summary ("1 session · 2 tasks · 1 file [1/4]") and grouped SESSIONS/TASKS/FILES results, while matches highlight in-place in the panels — a strong, legible pattern.
Fix: No change needed; the cyan accent border here is the clearest selection treatment in the app and could inform the other panels' selection styling.
nit
FILES group header shows with no visible row consistency
The FILES group label appears immediately above the key-hints line with the single file match not clearly visible in the group, making the count ("1 file") and the list briefly disagree.
Fix: Always render at least the matched file row under its group header, or hide a group header when its rows are scrolled out of the strip's visible height.

Theme picker Ctrl+Y

warning
Theme preview swatch is too small to evaluate visual
The picker lists nine themes with a tiny Accent/Status/Border/Modal-bg swatch block to the right; the swatches are only a few cells each, so you cannot really preview what a theme looks like before selecting it.
Fix: Enlarge the swatch into a small labeled palette strip, or live-apply the highlighted theme to the background TUI as a true preview while navigating.
nit
Light/Dark grouping is implicit usability
Light themes are tagged "(Light)" inline but dark themes carry no tag, so the dark/light split is inferred rather than grouped.
Fix: Add subtle "Dark" / "Light" subheadings (or a column) so users can jump to the family they want.

New-session / repo picker Ctrl+N

warning
Empty repo picker is a dead end for new users usability
The picker opens to "Repos (0) · No bookmarks — add via path input below" with an empty input. A first-run user with no bookmarks gets a near-blank modal and must already know to type a path; there is no browse/recent affordance.
Fix: Seed the picker with recently-used repos or the current working directory, and make the path input clearly focused with a placeholder example path.
nit
Picker modal feels under-sized for its job visual
The repo picker is a small box high on the screen with a dense hint line; for a primary action (new session) it reads as a minor popup rather than a key step.
Fix: Give the new-session picker more vertical room and a clearer title/step indicator so it matches the weight of the action.

Keybindings help + editor Ctrl+G

nit
Solid, scannable keybindings reference usability
Actions are grouped (Navigation / Sessions / Project / UI) in a clean two-column action→chord layout with a scrollbar and an inline rebind/reset footer — discoverable and consistent with the rest of the app.
Fix: No change needed; consider a top filter/search field given the list scrolls beyond one screen.
nit
Chord column is dim against group headers visual
The chord strings (ctrl+h, ctrl+l, …) render in a muted red that is lower-contrast than the action labels, so the actual keys — the thing users came for — are the least prominent text.
Fix: Slightly brighten the chord column or render chords in a boxed/keycap style so the binding is at least as legible as its description.
