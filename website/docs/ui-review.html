thurbox TUI — UI/UX Review

thurbox 0.0.0-dev theme: Doom generated 2026-06-03 09:30 UTC

This page is generated by the ui-review skill: it drives the real TUI in an isolated sandbox, screenshots every screen, and critiques each through four lenses — visual design, usability, consistency, and accessibility. Re-run the skill to refresh it.

Summary — 21 findings across 10 screens

10 warnings 11 nits 8 visual 8 usability 2 consistency 3 accessibility

Top recommendations

  1. Establish one "focused panel" accent color and apply it everywhere (session list, tasks, file viewer) — focus currently reads as red in some panels and green in others.
  2. Stop using red for non-error states (in-progress tasks): reserve red for errors so status colors don't alarm.
  3. Raise contrast on secondary text that carries real meaning — the header version, info-panel values, task "local" tag, and the keybindings chord column are all too dim.
  4. Back every color-only signal (status dots, swatches) with a glyph or short label for colorblind/low-vision users.
  5. Tighten dense overlays (keybindings help, info panel) with section spacing; expand under-filled ones (file viewer) by auto-expanding the first level.

Session list + terminal (default view) launch

warning
Header version string is near-invisible visual
The “v0.0.0-dev” version in the top bar is rendered in a very dim grey that nearly disappears against the dark header, while the “thurbox” wordmark and title are bright.
Fix: Lift the version to at least the muted-text contrast tier, or right-align it next to the agent badge where secondary metadata already lives.
warning
Hard to tell which pane has focus usability
The focused pane (the agent terminal) and the session list look almost equally weighted; a newcomer can’t immediately tell which pane has focus or that Enter/Ctrl+L moves between them.
Fix: Strengthen the focused-pane border accent and/or add a one-word focus hint (e.g. “▸ terminal”) so the active pane reads at a glance.
nit
Session row status alignment feels lopsided consistency
“Waiting” is right-aligned on the session row while the repo sub-line (“claude · sample-project”) is left-aligned and dimmer, which makes the row feel slightly unbalanced.
Fix: Keep a consistent two-column rhythm (name left, status right, repo as a full-width dim sub-row) and tighten the vertical gap.

warning
Ctrl+J produced no visible change with one session usability
With only one repo seeded, pressing Ctrl+J leaves the view identical to the default — there is no feedback that the navigation key did anything.
Fix: When navigation can’t move (single session / already at an end), flash the current row or show a brief toast so the key feels responsive rather than dead.

Session info panel (Ctrl+B) Ctrl+B

warning
Info panel is cramped and labels truncate visual
Squeezed into the left column, the info panel stacks Status, memory (“200.7 MB”), Usage, System and Automations tightly with little spacing; some values butt right against their labels.
Fix: Add one space of left padding inside the panel and a blank line between sections (Usage / System / Automations) to make the groups scannable.
warning
Status conveyed mostly by color dots accessibility
Automation/status indicators lean on small colored dots; at this density and contrast they’re hard to distinguish for low-vision or colorblind users.
Fix: Pair each dot with a short text/glyph label (e.g. “● active”, “○ idle”) so status isn’t color-only.

File viewer — repo tree (Ctrl+E) Ctrl+E

nit
File viewer shows only the repo root, lots of empty space visual
The right-hand file column displays “sample-project” at the top with the rest of the column empty until expanded; the panel reads as under-filled.
Fix: Auto-expand the first level (or the primary repo) on open so the viewer shows a useful tree immediately instead of a single collapsed node.
nit
Good: footer exposes file-viewer keys usability
The footer correctly switches to file-viewer-scoped hints (Move / Collapse-Expand / Open / search) when the viewer is focused — a nice discoverability win.
Fix: Keep this context-sensitive footer pattern; consider applying the same density to the other panels’ footers.

Tasks panel — todo list (Ctrl+W) Ctrl+W

warning
In-progress task recolors text red accessibility
The three statuses (☐ todo, ◐ in-progress, ☑ done) are distinguishable by glyph, which is good, but the in-progress row also recolors its text red — easy to misread as an error/blocker.
Fix: Reserve red for errors; use a neutral/accent hue for in-progress and keep the glyph as the primary signal.
nit
Tasks panel border accent differs from session list consistency
The Tasks panel uses a green accent border while the focused session list uses red; the two focused-panel treatments don’t share a single accent language.
Fix: Standardize one “focused” accent color across all panels so focus reads identically everywhere.
nit
“local” source label is very dim visual
The “local” source tag under the task list is rendered in a faint italic that’s easy to miss.
Fix: Slightly raise its contrast or move it inline with each task so the source is legible.

Automations pane (Ctrl+P) Ctrl+P

Automation cron string is dense and unexplained visual
The pane shows “nightly-triage — 0 9 * * * · spawn · in 21h 30m”; the raw cron expression next to a humanized “in 21h 30m” is redundant and hard to parse at a glance.

The pane surfaces “n new · e edit · Spc toggle · r run · d delete” inline — strong affordance for the available actions.

nit
Excellent live palette preview visual
The theme modal pairs the theme list with a live preview of Accent / Status / Border / Modal-bg swatches and the current preset id — this is a model panel.
Fix: No change needed; this is the strongest screen — consider reusing its label+swatch layout elsewhere.

The swatches show color blocks but not their roles beyond the row label; a colorblind user can’t verify, e.g., that accent ≠ status.
Fix: Add a tiny hex or name on hover/selection so the preview is verifiable without relying on color perception.

Keybindings help + editor (Ctrl+G) Ctrl+G

warning
Keybindings overlay is dense and low-contrast visual
The help overlay packs Navigation / Sessions / Project / UI / Clipboard sections into a tight grid where the chord column and description column are both dim, making it tiring to scan.
Fix: Increase row spacing, brighten the chord column (it’s the lookup key), and left-align descriptions to a consistent column.
nit

The footer of the editor lists capture/reset actions, but they’re rendered in the same dim tier as everything else, so the powerful “reset all” action hides.
