Installation

Thurbox needs three programs on your PATH: thurbox (with thurbox-cli), fleet and runtime-mux. Fleet manages the sessions, and runtime-mux runs them in tmux (psmux on native Windows). Install them in this order:

  1. Install them with the install script (From Binary). The other packages ship thurbox and thurbox-cli only (Fleet and runtime-mux).
  2. Run thurbox-cli doctor, then thurbox (First run).

From Binary #

One command on Linux and macOS. The install script downloads the latest release, detects your platform, verifies checksums, and installs thurbox, thurbox-cli, fleet, runtime-mux and workspace-git to ~/.local/bin. When it is done, it points at fleet init.

Thurbox v3 needs a 3.x release. Until one is published, the script installs the latest 2.x release, which has no Fleet; pin a 3.x tag with VERSION once one exists. 

curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh

Upgrading from 2.x. A 2.x install updates only within 2.x: neither the in-app update nor thurbox-cli update (--force included) moves it to 3.x. Run the install script again.

The script handles:

  • Platform detection (Linux/macOS, x86_64/aarch64)
  • Automatic version fetching with API rate limit fallback
  • SHA256 checksum verification
  • Creating ~/.local/bin if needed
  • Post-install instructions

export is not optional for the environment variables below. In VAR=x curl … | sh the assignment binds to curl, and the sh reading from the pipe never sees it — so the setting is silently ignored. Export it on its own line first.

Custom install directory

export INSTALL_DIR=/usr/local/bin
curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh

Specific version

export VERSION=vX.Y.Z   # a tag from the releases page
curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh

Without a pin you get the newest release. Every version is on the releases page.

Windows (PowerShell)

Native Windows defaults to psmux. Install psmux, a drop-in tmux clone on ConPTY that speaks the same control-mode protocol. psmux is a bit less stable, so please report anything you hit. To run sessions in a WSL distro instead, install Fleet inside the distro and follow it from Windows (Fleets).

On native Windows the install script is PowerShell, and it is the recommended route — unlike the winget and Chocolatey packages below, it always carries the newest release. It installs to %LOCALAPPDATA%\Programs\thurbox (added to your user PATH). 

irm https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.ps1 | iex

Set $env:THURBOX_VERSION = 'vX.Y.Z' before that line to pin a specific version instead of taking the newest. It installs the same five programs. Until a 3.x release is published, the newest is a 2.x release with no Fleet.

winget (Windows) #

On Windows, install the prebuilt x86_64 binaries with winget (Microsoft's package manager, bundled with Windows 10/11): 

winget install Thurbeen.thurbox

Installs thurbox.exe and thurbox-cli.exe from the GitHub Release as portable commands on your PATH . Needs psmux as the multiplexer, installed separately.

Release cadence. winget-pkgs is manually reviewed, so thurbox submits a new winget version on every release, but skips a submission while its previous one is still an open PR — wingetcreate can't update a pending PR, and a submission waits on review before it goes live. The latest build always ships immediately via the PowerShell installer above and GitHub Releases , so irm … install.ps1 | iex stays the recommended route on Windows; the winget channel intentionally trails a little.

Chocolatey (Windows) #

On Windows, install the prebuilt x86_64 binaries from the Chocolatey community repository : 

choco install thurbox

Installs thurbox.exe and thurbox-cli.exe from the GitHub Release and shims them onto your PATH . Needs psmux as the multiplexer, installed separately (there is no Chocolatey package for it). New versions go through community-repo moderation before they appear.

Release cadence. Unlike winget, the Chocolatey community repo is rate-limited on a calendar, so thurbox pushes a new Chocolatey version at most once every 30 days (intermediate releases are coalesced into the next push). The latest build always ships immediately via the PowerShell installer above and GitHub Releases , so irm … install.ps1 | iex stays the recommended route on Windows; the Chocolatey channel intentionally trails a little.

Homebrew #

On macOS or Linux, install the prebuilt binaries from the thurbox tap : 

brew install thurbeen/thurbox/thurbox

This installs thurbox and thurbox-cli , pulling in tmux and git as dependencies. Supported on macOS Apple Silicon and Linux x86_64 and aarch64 (Intel macOS has no release binary — build from source there).

Arch Linux (AUR) #

Thurbox is on the AUR as thurbox (builds from source) and thurbox-bin (prebuilt release binary). Install with your AUR helper: 

paru -S thurbox-bin   # prebuilt binary (fastest)
paru -S thurbox       # build from source

tmux is pulled in as a dependency. Swap paru for yay or your preferred helper.

Nix and NixOS #

The repository is a flake. It builds both binaries from source against Cargo.lock and puts tmux and git on their PATH , after anything you already have there. It covers x86_64 and aarch64 Linux and Apple Silicon macOS. CI builds it on x86_64 Linux only. 

nix run github:Thurbeen/thurbox                      # try it without installing
nix profile install github:Thurbeen/thurbox          # install into your profile

On NixOS, add the flake to your system flake and enable its module:

{
  inputs.thurbox.url = "github:Thurbeen/thurbox";

  outputs = { nixpkgs, thurbox, ... }: {
    nixosConfigurations.my-host = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        thurbox.nixosModules.default
        { programs.thurbox.enable = true; }
      ];
    };
  };
}

overlays.default adds pkgs.thurbox if you'd rather list the package yourself, and homeManagerModules.default offers the same programs.thurbox options under Home Manager.

A flake build isn't a release. It reports its version as 0.0.0-unstable-<date>+<commit> and never updates itself, because Nix owns the binary. To pin a version, point the input at a tag, for example github:Thurbeen/thurbox/vX.Y.Z .

Fleet and runtime-mux #

The install scripts (install.sh and install.ps1) ship fleet, runtime-mux and workspace-git beside Thurbox. Homebrew, the AUR, Nix, winget and Chocolatey ship thurbox and thurbox-cli only: run the install script as well, or build from source. To install Fleet alone, with no thurbox, see Install Fleet. Fleet's own documentation is in docs/fleet.

From Source # 

git clone https://github.com/Thurbeen/thurbox.git
cd thurbox
cargo build --release

This builds every program in the repository. The binaries are in target/release/: thurbox, thurbox-cli, fleet, runtime-mux and workspace-git. A source build is a development build (version 0.0.0-dev): it uses thurbox-dev in place of thurbox in its paths and its tmux socket.

First run # 

thurbox-cli doctor   # checks each Fleet, runtime-mux and the multiplexer
thurbox

thurbox-cli doctor names anything that is missing and how to install it. On a machine with no Fleet config, the first thurbox runs fleet init and says where it wrote the config. Thurbox starts fleet up on this machine when no Fleet manager runs.

Quick Start #

  1. Launch Thurbox — run thurbox in your terminal. You'll see the session sidebar and a terminal panel.
  2. Create a session — press Ctrl+N . Pick a place and a repository (optionally a worktree, Alt+W), name the session and its branch, then choose an agent.
  3. Work with the agent — the terminal panel shows the live agent session. All keys are forwarded to the PTY.
  4. Navigate — Ctrl+L / Ctrl+H cycle pane focus, Ctrl+J / Ctrl+K switch sessions.
  5. Quit — Ctrl+Q closes the interface. Fleet keeps every session running, and Thurbox shows them again on next launch.
  6. Make it yours — Ctrl+, then ] lists every pane and lets you turn one off, Ctrl+Y changes the palette, F1 rebinds any chord. Or just ask an agent — see just ask for it .

Configuration #

Every session is a Fleet Task, so session state is Fleet's. Thurbox keeps no database. Its configuration and its own state (session order, theme, keybindings, settings) are plain files under ~/.config/thurbox; bookmarks and logs are under ~/.local/share/thurbox ($XDG_CONFIG_HOME and $XDG_DATA_HOME respected). To follow a Fleet on another machine or in WSL, see Fleets.

Uninstall #

Every session is a Fleet Task, and Fleet keeps it running after Thurbox quits. Removing the binaries does not stop the sessions or remove their worktrees. Go through the steps below in order, because steps 1 and 2 need fleet and thurbox-cli, which step 3 removes. The paths are the defaults on Linux and macOS; Windows and other machines follow in step 5.

Moved something? thurbox-cli version --json prints Thurbox's tmux socket (tmux_socket), its directory (tmux_tmpdir) and the data directory (data_dir). They differ from the defaults for a development build (thurbox-dev), under THURBOX_DATA_DIR or THURBOX_SOCKET . The config directory follows THURBOX_CONFIG_DIR , then $XDG_CONFIG_HOME . Fleet's config follows FLEET_CONFIG. Substitute your values below.

1. Delete sessions and stop Fleet

Quit the TUI. Delete each session with fleet delete task <name>. The Fleet manager then stops the agent and removes the session's git worktree, so keep it running until fleet list task lists nothing. Only then stop the manager and remove Fleet's files. Committed work that exists nowhere else stays under refs/fleet/preserved/ in the source repository. Destructive: this ends the agent session, and any unsaved agent conversation with it. 

fleet list task
fleet delete task <name>       # once per session
fleet list task                 # repeat until it lists nothing

Then stop this Fleet's manager, and only it: fleet version --json names the process that holds the lease (fleet-up-<pid>), so another Fleet on the same machine keeps running. The snippet signals that PID only while the lease is held and the process is still Fleet's up (also when it runs as fleet --config <path> up). 

pid=$(fleet version --json | jq -r 'select(.manager.held == true) | .manager.holder | ltrimstr("fleet-up-")')
[ -n "$pid" ] && ps -p "$pid" -o args= | grep -qE '(^|/)fleet( .*)? up( |$)' && kill "$pid"
tmux -L runtime-mux kill-server # runtime-mux's tmux server; skip it if another Fleet still uses it

Thurbox runs companion shells (Ctrl+T) on its own tmux socket. Stop that server with the socket and directory thurbox-cli version --json reports: 

TMUX_TMPDIR=~/.local/share/thurbox/tmux tmux -L thurbox kill-server

2. Remove what Fleet added to other tools

Thurbox writes nothing outside its own directories, except the git worktrees of step 1 and the Windows PATH entry of step 5. Fleet writes into an agent's own config directory only when you ran fleet integration install. Remove those integrations: 

fleet integration status --all
fleet integration uninstall --all

3. Remove the binaries

Every install method ships thurbox and thurbox-cli; the install scripts also ship fleet, runtime-mux and workspace-git. 

# install.sh: the five programs and the LICENSE beside them, in ~/.local/bin or your INSTALL_DIR
cd ~/.local/bin && rm -f thurbox thurbox-cli fleet runtime-mux workspace-git LICENSE

brew uninstall thurbox          # Homebrew
paru -R thurbox-bin             # Arch (AUR), prebuilt package
paru -R thurbox                 # Arch (AUR), built from source
nix profile remove thurbox      # Nix, installed with nix profile install

On NixOS or Home Manager, delete programs.thurbox , thurbox.nixosModules.default or thurbox.homeManagerModules.default and the thurbox input from your flake, then rebuild with sudo nixos-rebuild switch or home-manager switch . The store copy stays until nix-collect-garbage .

A source build installs nothing: delete the clone, and any copy of its binaries you put on your PATH . Windows is in step 5.

4. Optionally remove config and state

Delete Thurbox's and Fleet's own directories. Destructive: this erases Thurbox's settings, theme, keybindings, interface customisations and logs, and Fleet's config, harness profiles and store (a later reinstall starts from scratch). 

rm -rf ~/.local/share/thurbox ~/.config/thurbox
rm -rf ~/.local/share/fleet ~/.config/fleet

5. Windows and other machines

Windows. The same steps, in PowerShell. Sessions run on psmux instead of tmux. Thurbox's configuration lives in %APPDATA%\thurbox and its state in %LOCALAPPDATA%\thurbox ; Fleet's config is in %APPDATA%\fleet and its store in %LOCALAPPDATA%\fleet . 

# 1. Delete sessions with fleet delete task, wait until fleet list task
#    lists nothing, then stop this Fleet's manager (fleet.exe is in the
#    install directory, so it must not be running when step 3 removes it)
$lease = (fleet version --json | ConvertFrom-Json).manager
if ($lease.held) {
  $p = Get-Process -Id ($lease.holder -replace '^fleet-up-', '') -ErrorAction SilentlyContinue
  if ($p -and $p.ProcessName -eq 'fleet') { Stop-Process -Id $p.Id }
}
psmux -L runtime-mux kill-server   # runtime-mux's psmux server; skip it if another Fleet still uses it
psmux -L thurbox kill-server

# 3. Remove the binaries
winget uninstall Thurbeen.thurbox       # winget
choco uninstall thurbox                 # Chocolatey
# install.ps1: the install directory, and its entry in your user PATH
$dir = "$env:LOCALAPPDATA\Programs\thurbox"   # or your THURBOX_INSTALL_DIR
Remove-Item -Recurse -Force $dir
$path = [Environment]::GetEnvironmentVariable('Path', 'User') -split ';' |
  Where-Object { $_ -and $_ -ne $dir }
[Environment]::SetEnvironmentVariable('Path', ($path -join ';'), 'User')

# 4. Optional (destructive): config and state
Remove-Item -Recurse -Force "$env:APPDATA\thurbox", "$env:LOCALAPPDATA\thurbox",
  "$env:APPDATA\fleet", "$env:LOCALAPPDATA\fleet"

Remote hosts. Sessions Thurbox v2 ran on an ssh: or wsl: host from its hosts.toml ran on that host, and Thurbox never cleans a host up for you. On each host it may have left a tmux server, worktrees under ~/.local/share/thurbox/worktrees (or the host's worktrees_dir ), a copy of thurbox-cli and its database under ~/.local/share/thurbox , and, from Thurbox v2, the same agent hook entries as step 2. Run this on the host, through ssh <host> or wsl -d <distro> . Destructive in the same way as steps 1 and 4. Use the host's socket from that old hosts.toml if you set one. 

tmux -L thurbox kill-server
for wt in ~/.local/share/thurbox/worktrees/*/*/; do
  [ -e "$wt/.git" ] || continue
  git -C "$wt" worktree remove --force "$wt"
done
rm -rf ~/.local/share/thurbox ~/.config/thurbox

A Windows host is the same with psmux and the Windows paths above.

A Fleet on another machine or in WSL. Its sessions run there, and Thurbox never cleans that machine up for you. Delete its sessions from Thurbox or with fleet delete task there, wait until fleet list task there lists nothing, then remove its [fleets.<name>] table from Thurbox's settings.toml. To remove Fleet from that machine, stop its manager only then, and follow steps 1 to 4 there, through ssh <machine> or wsl -d <distro>: 

systemctl --user disable --now fleet.service
rm ~/.config/systemd/user/fleet.service
