Frequently Asked Questions

Short answers to the most common questions about Thurbox. For depth, follow the links into the rest of the docs.

What is Thurbox?

Thurbox is a multi-session TUI for coding agents — the agents Fleet has harness profiles for — running inside persistent multiplexer panes. Every session is a Fleet Task: Fleet starts it in a git worktree of the repository you pick and keeps it running, so sessions survive crashes and restarts.

How is Thurbox different from other parallel coding-agent tools?

Unlike tools such as Conductor, Claude Squad, or Cursor, Thurbox uses an external multiplexer (tmux, or psmux on Windows) for its sessions, runs as a lightweight terminal UI rather than an Electron or native desktop app, and launches the unmodified vendor CLI rather than its own model. Every pane of the interface is a Lua file you can edit, turn off or replace. See the comparison for the full breakdown.

Which coding agents does Thurbox support?

Thurbox runs the agents Fleet has harness profiles for: Fleet bundles Claude Code, Codex, pi, opencode, kilo, omp, Qwen Code, GitHub Copilot CLI and Kimi Code. A new agent is a new profile in Fleet, not a change to Thurbox. Fleet launches each agent's own CLI unmodified and never touches the agent's model, prompts, or permissions.

How do I install Thurbox?

On Linux or macOS, run curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh. It is also available via Homebrew (brew install thurbeen/thurbox/thurbox), the AUR (thurbox or thurbox-bin), Nix (nix profile install github:Thurbeen/thurbox), and on Windows via winget (winget install Thurbeen.thurbox) or Chocolatey (choco install thurbox). Both of those channels are moderated and lag behind the newest release — Chocolatey by up to 30 days, winget by however long its manifest PR waits for review — so the PowerShell installer (irm https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.ps1 | iex) is the recommended route on Windows. You can also build from source with cargo build --release. See installation for details.

Which platforms does Thurbox run on? Does it support remote machines?

Thurbox runs on Linux, macOS, and Windows. It defaults to tmux 3.2+ on Linux/macOS and psmux 3.3.8+ on Windows. It can also run sessions on a remote host over SSH while the TUI runs locally — remote hosts are declared in hosts.toml.

Do my sessions survive a crash or restart?

Yes. Each session runs inside a persistent multiplexer session, so the agent processes keep running even if Thurbox crashes or you close and reopen it. Every session is a Fleet Task, so a restarted Thurbox shows the same sessions.

Why is a tmux server still running that tmux -L thurbox ls cannot see?

tmux's default socket directory is /tmp, which macOS sweeps, and a server whose socket file is gone keeps running with no way in. Thurbox now keeps its socket under its data dir (~/.local/share/thurbox/tmux/) and, if a socket is lost anyway, recreates it with SIGUSR1 instead of starting a second server. An older thurbox started a second one, leaving the first orphaned. Find it with ps -axo pid,args | grep '[t]mux -L thurbox': a server whose socket file is missing is the orphan. Once a second server owns the path, killing the orphan (kill <pid>) is the only option. See docs/thurbox/config.md → An orphaned tmux server.

Is Thurbox free and open source?

Yes. Thurbox is open source under the MIT license and free to use.

Can I use Thurbox without the TUI, headlessly?

Yes. Every session is a Fleet Task, so Fleet's command line, fleet, creates, lists, sends to and deletes sessions headlessly, and the TUI shows every change. thurbox-cli covers the interface's own files and automations. This makes Thurbox scriptable for automation and CI.
