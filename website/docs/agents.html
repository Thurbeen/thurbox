Agents

Thurbox 3.0 keeps no agent registry. A session is a Fleet Task, and the agent it runs is the Task's harness: Fleet starts it, resumes it and reports its status through its harness profiles.

Which agents a session can run #

The new-session flow offers the harnesses Fleet has profiles for, as fleet version --json lists them under harnesses. Fleet bundles claude (also claude-code), codex, pi, opencode, kilo, omp, qwen, copilot and kimi. thurbox-cli doctor lists them beside the Fleet in force.

How an agent is launched, resumed and watched #

The harness profile owns the command, its arguments, the resume command and the status hooks. Fleet wires those hooks when it launches the agent, so Thurbox installs nothing into an agent's own configuration. Kimi Code is the exception: it reads hooks only from its own config file, so run fleet integration install kimi once before using it. No model is ever passed: each agent runs with its own default configuration.

Adding an agent #

A new agent is a new harness profile in Fleet, not a change to Thurbox.
