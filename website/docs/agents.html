Agents

Thurbox 3.0 keeps no agent registry. A session is a Fleet Task, and the agent it runs is the Task's harness: Fleet starts it, resumes it and reports its status through its harness profiles. Thurbox no longer reads agents.toml.

Which agents a session can run #

The new-session flow offers the harnesses Fleet has profiles for, as fleet version --json lists them under harnesses. Today those are claude (also spelled claude-code) and codex. thurbox-cli doctor lists them beside the Fleet in force.

How an agent is launched, resumed and watched #

The harness profile owns the command, its arguments, the resume command and the status hooks. Fleet wires those hooks when it launches the agent, so Thurbox installs nothing into an agent's own configuration. No model is ever passed: each agent runs with its own default configuration.

Adding an agent #

A new agent is a new harness profile in Fleet, not a change to Thurbox.

An agents.toml from 2.x #

An agents.toml left from Thurbox 2.x is not read, and can be deleted.
