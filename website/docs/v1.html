Using v1

thurbox 2.0 replaced the interface. If you were using a pane it no longer has, you do not have to give it up: 1.x is still maintained and still gets patch releases.

Nothing moves you without asking. The first time thurbox 2.x starts on a profile that has sessions, it stops and tells you what changed before touching anything. Declining turns auto-update off for you and prints the command below — it does not want you upgraded by accident.

What v1 has that the current interface does not #

Six surfaces. Three have no replacement yet; three moved to thurbox-cli, where the data and behaviour are the same.

Surface v1 Now
Code review Ctrl+X / F7 Nothing yet — the largest gap
File viewer Ctrl+E / F3 Nothing yet
Info panel Ctrl+B / F2 Nothing yet
Tasks F5 thurbox-cli task
Automations Ctrl+P thurbox-cli automation — and they still fire on their own
Restore deleted Ctrl+U thurbox-cli session restore

Everything else is unchanged, because only the interface was replaced: sessions, git worktrees, remote SSH and WSL hosts, agent definitions, extensions, hooks and status reporting, the mailbox queue, themes, notifications, and the whole of thurbox-cli.

Staying on v1, or going back #

Pin a 1.x version and turn auto-update off, or the next launch will bring you forward again: 

export VERSION=v1.8.6
curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh

Then set auto_update = false under [features] in ~/.config/thurbox/settings.toml. Declining the first-launch prompt does both of these for you and says so.

export matters: in VERSION=x curl … | sh the assignment binds to curl, and the sh reading from the pipe never sees it. The newest 1.x patch is on the releases page.

Your sessions are safe either way #

Both versions read and write the same database at the same schema version, so nothing is migrated and nothing is stranded. Sessions, worktrees, tasks and automations are the same records whichever you run, and the agents themselves are held by tmux rather than by thurbox — so switching does not interrupt a turn in progress. You can move back and forth as often as you like.

What 1.x will and will not get #

  • Will: bug fixes, security fixes, and fixes to the session engine, backends and CLI, released as 1.x patch versions from the 1.x branch.
  • Will not: new features. Those land on the current line, where the interface is a plugin set rather than a fixed set of panes.

The reference documentation on this site describes the current interface. For v1's own docs, read them at the tag you are running — the 1.x branch carries the versions that match it, including its keybindings, its feature notes and its architecture decisions.

Coming forward later #

Reinstall without pinning a version and answer yes at the prompt. If what kept you on v1 was one of the three missing panes, they are tracked in the repository under openspec/changes/v2-parity-gaps/ — and because panes are now files, a replacement does not have to come from us. See the interface for what writing one involves.
