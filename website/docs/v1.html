Using v1

2.x is the current line, and what every installer gives you by default. 1.x is still maintained and still gets patch releases, so if you were using a pane 2.x does not have, you do not have to give it up — this page is how to stay on it or go back.

The last 1.x release is v1.8.7. Every installer takes the newest release unless you pin a version, so staying here is a deliberate two-step: pin, then turn auto-update off. Both are below.

Nothing moves you without asking. The first time thurbox 2.x starts on a profile that has sessions, it stops and tells you what changed before touching anything. Declining turns auto-update off for you and prints the command below — it does not want you upgraded by accident.

What v1 has that the current interface does not #

Six surfaces. Three moved to thurbox-cli, where the data and behaviour are the same; two came back as panes you install; one has no replacement.

Surface v1 Now
Code review Ctrl+X / F7 The thurbox-code-review plugin — same chord
File viewer Ctrl+E / F3 Nothing yet
Info panel Ctrl+B / F2 The thurbox-info-panel plugin
Tasks F5 thurbox-cli task
Automations Ctrl+P thurbox-cli automation — and they still fire on their own
Restore deleted Ctrl+U thurbox-cli session restore

Everything else is unchanged, because only the interface was replaced: sessions, git worktrees, remote SSH and WSL hosts, agent definitions, extensions, hooks and status reporting, the mailbox queue, themes, notifications, and the whole of thurbox-cli.

Staying on v1, or going back #

Pin a 1.x version. On Linux and macOS:

export VERSION=v1.8.7
curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh

On Windows:

$env:THURBOX_VERSION = 'v1.8.7'
irm https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.ps1 | iex

export / $env: on its own line matters: in VERSION=x curl … | sh the assignment binds to curl, and the sh reading from the pipe never sees it — you would get the newest release, silently. The newest 1.x patch is on the releases page.

Auto-update will not carry you into 2.x. thurbox never crosses a major version on its own: a 1.x install is told that 2.x exists and keeps updating along 1.x. thurbox-cli update --force is the deliberate way across, and the first 2.x launch of a profile with v1 history asks before anything changes.

One caveat, because it decides what you should do today: that guard lives in the binary, and releases up to v1.8.7 predate it. If you are already on 1.8.x, set auto_update = false under [features] in ~/.config/thurbox/settings.toml until a 1.x patch carrying the guard ships. Declining the first-launch prompt writes that for you and says so.

Your sessions are safe either way #

Both versions read and write the same database at the same schema version, so nothing is migrated and nothing is stranded. Sessions, worktrees, tasks and automations are the same records whichever you run, and the agents themselves are held by tmux rather than by thurbox — so switching does not interrupt a turn in progress. You can move back and forth as often as you like.

What 1.x will and will not get #

  • Will: bug fixes, security fixes, and fixes to the session engine, backends and CLI, released as 1.x patch versions from the v1.x branch.
  • Will not: new features. Those land on the 2.x line, where the interface is a plugin set rather than a fixed set of panes.

The reference documentation on this site describes the current interface. For v1's own docs, read them at the tag you are running — the v1.x branch carries the versions that match it, including its keybindings, its feature notes and its architecture decisions.

Coming forward later #

Reinstall without pinning a version and answer yes at the prompt. If what kept you on v1 was one of the three missing panes, code review and the info panel are back as installable panes; only the file viewer has no replacement. And because panes are now files, one does not have to come from us. See the interface for what writing one involves.
