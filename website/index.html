Orchestrate agents

thurbox is the terminal interface to watch and drive your coding agents. Fleet runs them and keeps them running.

Thurbox Fleet

The interface

thurbox

thurbox is a terminal interface on top of one or more Fleets. It shows every session of every Fleet in one list, with the agent's live terminal beside it. Every pane is a Lua file you can move, turn off or replace.

Quit thurbox and the agents keep running: Fleet runs them.

Get started with thurbox

curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh
thurbox

The first thurbox runs fleet init and starts Fleet on this machine. On Windows, run irm https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.ps1 | iex. Other install routes →

The engine

Fleet

Fleet runs coding-agent sessions. Each session is a Task: a file that names the agent, the place it runs, the repository and the brief. You apply it with fleet apply, and Fleet starts the session, keeps it running, delivers your messages and records the result.

Fleet works on its own. It is headless and needs no thurbox.

What Fleet is → Fleet features → 

fleet apply -f fix-login.json
fleet list task
fleet send fix-login "Run the tests too"

Get started with Fleet alone

curl -fsSL https://raw.githubusercontent.com/Thurbeen/thurbox/main/scripts/install.sh | sh -s -- --fleet-only
fleet init
fleet doctor
fleet up

--fleet-only installs fleet, runtime-mux and workspace-git, and nothing else. Install Fleet →

How it works

One interface over an engine that reconciles

thurbox is the screen. Fleet is the engine. Scroll to watch them work.

  1. 1One list

    thurbox shows the sessions of every Fleet that settings.toml lists, in one list. A row's id is <fleet>:<task>.

  2. 2Several Fleets

    Each Fleet runs its own Tasks: on this machine, on another one over ssh, or in a WSL distro. On each machine, fleet up runs its Fleet.

  3. 3Quit, and they keep running

    Fleet runs the sessions, not thurbox. Quit thurbox and every agent keeps working. A Fleet that cannot be reached keeps its rows, marked unreachable.

  1. 1Declare

    You write what you want as a resource. A Task names the agent, the place and the brief; fleet apply, thurbox or a script puts it in the store. TaskConfig, EnvProvider, ChangeRequest and CronTask are resources too.

  2. 2Compare

    Controllers, run by fleet up, read each spec and observe the runtime. A Task that should run and has no session is a gap to close.

  3. 3Act

    They close the gap through the runtime: make the workspace, start the session, type the brief. The manager records each effect's intent before it runs it.

  4. 4Write back, sweep again

    They write the phase and the session's state back to the status, then sweep again. An observation they cannot read never counts as the session being gone.
